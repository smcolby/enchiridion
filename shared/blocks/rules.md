A scoped coding-rules catalog is installed as the `rules` skill. Before creating or modifying any file, in any directory, invoke the `rules` skill. Read the index it returns, then apply rules by tier: read every `always` rule, every `scoped` rule whose scope matches the target file, and every `requested` rule whose description matches the current task. Read an `invoked` rule only when the user or an active playbook names it. Do not write or edit any file until this step is complete. Before authoring any PR body or description, invoke the skill, read the `pr-authoring` rule, and follow its template-discovery and fallback-structure steps before writing a single word of the body. Before claiming code is correct, complete, or passing (including after running tests or reviewing a diff), invoke the skill and read the `code-honesty` rule.
